## 1. CORE PHILOSOPHY & SCREEN VS. VOICE (CRITICAL)

### Rule 1: "Screen for Orientation, Voice for Speech"
- **STRICT PROHIBITION**: NEVER duplicate the `voiceOverText` or copy long sentences verbatim onto the HTML screen. DO NOT output paragraphs, multi-line narrative blocks, or body copy describing the topic.
- **Role Distinction**:
  - **Screen (Visual HTML)**: Exclusively for visual orientation, mental models, structure, and instant comprehension.
  - **Voice (TTS `voiceOverText`)**: Exclusively carries the explanation, narration, storytelling, and nuanced speech.
- **Strict On-Screen Element Budget per Scene**:

    3. *Icon / Visual Badge*: High-quality inline SVG icon/symbol + brief 1-3 word anchor tag.
    4. *Key Concept*: Bold takeaway phrase or keyword chip.

### Rule 2: Semantic Scene Segmentation & Visual Anchors
- **1 Scene = 1 Mental Model**: Do not fragment scenes arbitrarily by grammar clauses or pauses. Each scene must represent a complete cognitive concept or logical step.
- **Visual Anchor Continuity**: Across consecutive scenes (Scene N -> Scene N+1), preserve at least ONE visual anchor (e.g. consistent accent color role, persistent layout axis, recurring icon badge, or continuous spatial anchor) so the viewer feels continuity rather than jarring disorientation.

## 2. VISUAL DESIGN, TYPOGRAPHY & LAYOUT STANDARDS

### Typography Hierarchy & Exact Scales (Based on 1080p canvas)
- **Display / Main Title**: 64px–80px bold/extra-bold (`font-weight: 800/900`). Dominant visual hierarchy.
- **Sub-heading / Section Tag**: 28px–36px medium/semi-bold. Clear secondary orientation.
- **Key Stat / Highlight Number**: 48px–72px bold with high contrast or accent color.
- **Body Note / Micro-label**: 18px–22px readable, strictly limited to short notes or labels (≤ 8 words per label).

### Negative Space & Breathing Room
- **Mandatory 35%–45% Negative Space**: At least 35%–45% of the total screen canvas MUST remain clean, unoccupied breathing space.
- Avoid edge-to-edge clutter. Use generous margins (padding ≥ 60px–100px from viewport borders) and structured gutters.

### Anti-Card Slop (Design Sophistication)
- **DO NOT** default to wrapping every single item in rounded glassmorphic boxes (`rgba(255,255,255,0.05)`). Overuse of floating glass cards creates cheap "AI template slop".
- Use the **Boundary Strength Ladder**:
  1. *Spacing & Alignment*: Group related items with deliberate whitespace and edge-alignment (lightest & most sophisticated).
  2. *Hairline Rules / Dividers*: Subtle borders or accent separator lines (`border-bottom: 1px solid rgba(255,255,255,0.12)`).
  3. *Tonal Tint Fields*: Soft flat background tints instead of heavy borders.
  4. *Outlines / Contours*: Crisp thin strokes without filled background.
  5. *Cards / Panels*: Use cards ONLY when elements require a distinct physical plane (e.g., floating modal or elevated comparison).
- Embrace asymmetric balance, editorial typography layouts, and split-screen negative space.

### Modern Depth & Color Harmony
- Curated color palettes: High-contrast ratios between background and foreground.
- Use multi-stop gradients sparingly for text highlights (`background: linear-gradient(...)`, `-webkit-background-clip: text`, `-webkit-text-fill-color: transparent`) or subtle atmospheric glows.
- Inline SVGs for crisp geometric icons, circular progress indicators, and charts.

## 3. SCENE TIMELINE PATTERN & DYNAMIC DURATION

Every scene `jsCode` MUST use the string placeholder `{{SCENE_DURATION}}` as the scene's exact duration in seconds.

**Scene Animation Lifecycle Template:**
```javascript
(function() {
  const dur = {{SCENE_DURATION}};
  const tl = gsap.timeline();

  // 1. Entrance (0.0s - 0.6s)
  tl.to('#scene_1', { opacity: 1, duration: 0.4, ease: 'power2.out' }, 0)
    .from('#scene_1 .title-word', { 
      y: 40, 
      opacity: 0, 
      stagger: 0.08, 
      duration: 0.6, 
      ease: 'back.out(1.7)' 
    }, 0.1)
    .from('#scene_1 .focus-anchor', { 
      scale: 0.9, 
      opacity: 0, 
      stagger: 0.12, 
      duration: 0.6, 
      ease: 'power3.out' 
    }, 0.3);

  // 2. Continuous Ambient / Main Motion (0.5s -> (dur - 0.5s))
  // Calculate remaining duration for ambient motion so animation doesn't freeze mid-scene!
  const ambientDur = Math.max(0.5, dur - 1.0);
  tl.to('#scene_1 .hero-graphic', { 
    rotation: 360, 
    duration: ambientDur, 
    ease: 'none' 
  }, 0.5)
  .to('#scene_1 .glow-effect', { 
    scale: 1.15, 
    opacity: 0.7, 
    yoyo: true, 
    repeat: 1, 
    duration: ambientDur / 2, 
    ease: 'sine.inOut' 
  }, 0.5);

  // 3. Exit Transition ((dur - 0.5s) -> dur)
  tl.to('#scene_1', { 
    opacity: 0, 
    scale: 0.96, 
    duration: 0.5, 
    ease: 'power2.in' 
  }, Math.max(0, dur - 0.5));

  window.__registerScene('scene_1', tl, dur);
})();
```

**CRITICAL MOTION RULES:**
- **NEVER** use `repeat: -1` in any GSAP tween or timeline. Any repeating motion must have a finite count (e.g. `repeat: 1`, `repeat: 2`) or use durations bounded by `ambientDur`. Infinite repeats corrupt timeline seeking and blackout subsequent scenes.
- Every scene must end with `window.__registerScene('<scene_id>', tl, dur);`.
- Do not redefine or overwrite `window.__registerScene`, `window.__masterTimeline`, or `window.__ready`.

## 4. LIME MOTION CONSTITUTION & TOKENS

All GSAP animation parameters MUST strictly adhere to the LIME Motion Tokens system.

### 4.1 Duration Tokens
- `dur.micro`: 0.15s–0.20s (150–200ms) — Micro-feedback: hover, click, icon tick, subtle checkmark.
- `dur.fast`: 0.25s–0.35s (250–350ms) — Secondary accents: sub-tags, chip entrance, secondary labels leaving/entering.
- `dur.base`: 0.45s–0.60s (450–600ms) — Default scene motion: primary visual cards, main title transitions.
- `dur.slow`: 0.70s–0.90s (700–900ms) — Heavy emphasis, key visual focal point shift, major morphing.
- `dur.cinematic`: 1.00s–1.40s (1000–1400ms) — Cold-open reveals, sweeping camera pan/zoom, grand outro lockup.
*Golden Rule*: "Không giải thích được duration bằng intent thì giảm nó một nửa."

### 4.2 Easing Tokens & GSAP Mapping
- `ease.enter` -> `expo.out` (Elements entering frame: snappy deceleration, soft settle).
- `ease.pop` -> `back.out(1.7)` (Elements needing slight organic overshoot: badge, icon chip, metric callout).
- `ease.playful` -> `elastic.out(1, 0.5)` (Playful accent or emotional beat; strictly max 1 occurrence per scene).
- `ease.camera` -> `circ.out` (Camera pan, zoom-through, long-distance spatial sweeps).
- `ease.flow` -> `sine.inOut` (Continuous background ambient movement, subtle floating oscillation).

### 4.3 Pattern Stagger Tokens
- `stagger.grid`: 0.04s — Dense grids, multiple icons, matrix cells.
- `stagger.list`: 0.08s — Ordered items, bullet takeaways, checklist rows, sequential title words.
- `stagger.dramatic`: 0.15s — Impactful, high-tension beats, minimal key anchors.

## 5. 5 ANTI-SLOP MOTION LAWS (STRICT CONTRACT)

1. **Cấm fade opacity 0->1 làm chuyển động duy nhất của một phần tử**: Mọi lần xuất hiện phải kèm transform (vị trí y/x, scale, hoặc clip-path/mask). Opacity đơn độc bị coi là cheap slideshow slop.
2. **Cấm easing tuyến tính (`linear` / `none` trong GSAP)** cho mọi chuyển động trừ thanh tiến trình (progress bar) và chuyển động nền tốc độ hằng số có lý do ghi rõ.
3. **Mọi move phải có damping hoặc overshoot**: Hoặc dùng token easing ở bảng 4.2, hoặc khai báo spring; cấm tween "đi đều rồi dừng đột ngột" (linear-to-stop).
4. **Cấm 2 scene liên tiếp dùng cùng một cơ chế vào cảnh (entrance)**: Sự lặp lại liên tiếp cùng một kiểu entrance (ví dụ cả 2 scene đều trượt từ dưới lên) là dấu hiệu slideshow.
5. **Mọi duration/easing/stagger phải tham chiếu token**: Tự chế thông số bừa bãi ngoài hệ thống token là lỗi, Phase 1 phải reject và retry.

## 6. BOUNDARY & CARRY CONTINUITY CONTRACT (SCENE TRANSITIONS)

Every multi-scene video script MUST declare a continuous carry plan across scene boundaries.
- **Boundaries Count**: Exactly `scenes.length - 1` boundaries connecting consecutive scenes.
- **Boundary Continuity**: `boundaries[i].fromScene === scenes[i].id` and `boundaries[i].toScene === scenes[i+1].id`.
- **Carry Mechanism Enum**:
  * `morph`: Hero element morphs smoothly into the focal anchor of the next scene.
  * `zoomThrough`: Camera rushes through an aperture or card into the next scene's spatial plane.
  * `iris`: Circular or geometric aperture expansion revealing the next scene.
  * `gather`: Dispersed elements collapse together to form the seed of the next scene.
  * `handoff`: One active element passes velocity or visual focus to a receiving element.
  * `hardCut`: Instant cut — **STRICTLY REQUIRES** a non-empty `reason` justifying the narrative impact.

## 7. RHYTHM CONSTRAINTS (NUMERICAL VERIFICATION)

Across the sequence of scenes (when script has ≥ 2 scenes):
- **Shot Duration Contrast**: Tỉ số shot dài nhất / ngắn nhất phải đạt `max/min >= 4`.
- **Near-Still Breathing Beat**: Script MUST have at least ONE near-still section lasting `≥ 1.5s` (declared via scene `nearStill: { from: number, to: number }` with `(to - from) >= 1.5` or specified in `visualDescription`).
- **Anti-Uniform Cadence**: Cấm nhịp đều đơn điệu. Hệ số biến thiên độ dài cảnh $CV = \text{stdDev} / \text{mean} \ge 0.3$.

## 8. PROCEDURAL CHARACTERS (SPEC F CONTRACT)

When narrative or explanatory context benefits from a human anchor, character guide, or presenter, scenes can declare `characterActions[]`:
- `characterId`: Unique identifier (e.g. `"guide"`, `"narrator"`, `"hero"`). Deterministic avatar appearance is automatically derived from `(seed, characterId)`.
- `action`:
  * `"enter"`: Character enters stage into position from offscreen (`direction`: `"left"` or `"right"`).
  * `"walk"` / `"run"`: Locomotion moves across stage.
  * `"idle"`: Standing resting pose with natural breathing and subtle sway.
  * `"emote"`: Expresses emotion on face and body gestures (`"happy"`, `"sad"`, `"surprised"`, `"angry"`, `"thinking"`). Zero external image assets; rendered procedurally.
  * `"exit"`: Character moves outward offscreen.
- `tStart` and `tEnd`: Action timing interval in seconds (e.g. `tStart: 0.0, tEnd: 2.0`).
- `position`: Coordinates `{ x: number, y: number }` (default center bottom around `{ x: 960, y: 720 }`).
- `scale`: Scaling factor (default 1.0).
- `direction`: `"left"` or `"right"` (facing direction).
- Example:

## 10. MOTION BLOCKS TOOLKIT (`window.__block`)

Complex UI is provided by runtime helpers. Prefer them over hand-rolling large DOM/CSS.

**Core blocks (always injected):**
- `kinetic-type` — stagger words / typewriter / word-swap
- `code-diff` — macOS IDE chrome + add/del lines
- `bar-chart` — animated bars + count-up values
- `device-showcase` — phone/laptop 3D mockup
- `chat-exchange` — user/assistant bubbles

**Usage pattern:**
```html
<div class="scene" id="scene_1">
  <div class="block-mount" style="width:100%;height:100%;"></div>
</div>
```
```javascript
(function() {
  const dur = {{SCENE_DURATION}};
  const tl = gsap.timeline();
  tl.to('#scene_1', { opacity: 1, duration: 0.4 }, 0);
  const mount = document.querySelector('#scene_1 .block-mount');
  const root = window.__block('kinetic-type', mount, {
    kicker: 'HOOK',
    text: 'Stop Guessing',
    mode: 'stagger-words'
  });
  window.__block.animate('kinetic-type', root, tl, { at: 0.15, duration: 1.0 });
  tl.to('#scene_1', { opacity: 0, duration: 0.45 }, Math.max(0, dur - 0.45));
  window.__registerScene('scene_1', tl, dur);
})();
```

Also available: `window.__sm()` / `window.__fx()` for stickman comic scenes.
